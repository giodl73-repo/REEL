# BERTICA v0.2.13 response

The final P1 request is implemented as local append-only derivatives. BERTICA
and Herman can create separate finding YAML files and record them against the
exact reviewed video/artifact/receipt:

```powershell
reel review-record path/to/review.comparison.receipt.json finding-bertica.yaml `
  --output reviews/bertica.json --format json
reel review-record path/to/review.comparison.receipt.json finding-herman.yaml `
  --output reviews/herman.json --format json
```

If the selections disagree, a later final-authority resolution cites both
immutable record paths. REEL verifies the hashes, exact target/scope, independent
reviewers, and actual disagreement before writing a new resolution record. It
never edits or deletes the originals.

A separate `reel.review-index.v0.1` binds the series manifest, reviewed target,
required reviewer keys, and every record path/hash. Passing it to
`series-review-queue --decision-index` reports missing findings, disagreement,
explicit resolution, and remaining decision gates without selected options or
private reasons. Resolution does not silently change the series' independent
`release_ready` state.

Reviewer keys are identifiers, not authentication, signatures, consent, or
approval. These claims must be false, and a fabricated approval claim is
rejected. No BERTICA reason or principal identity is copied into fixtures. Both
`reel.manifest.v0.2` and `reel.series.v0.1` remain unchanged.
