# Guarded retained job close

The native workflow adapter now calls the unchanged qualified EVID-151
`slots::close` interface. No new cache, actor lease or protection protocol is
introduced. The original vendored module and its tests remain source-pinned.

```text
reel-workflow-native prepare-close JOURNAL PROFILE TARGET NEW_TICKET --apply
reel-workflow-native stage-close TICKET TICKET_SHA256 NEW_STAGE_RECEIPT --apply
reel-workflow-native close-job TICKET TICKET_SHA256 NEW_RECEIPT --apply
reel-workflow-native recover-close TICKET TICKET_SHA256 NEW_RECEIPT --apply
```

Preparation requires an actually retained original journal, exact result and
acknowledgement, original runtime bytes and full native retained proof. It
previews the unchanged source-clear and positive-handoff limits without changing
the actor. Its ticket pins the closer runtime, original job/activation, operation
identity and explicitly selected ready handoff retainer. The closer has its own
pinned executable; it reads the original producer pin without impersonating it.

Execution rechecks the original retained job before invoking the qualified close.
Positive retained protection precedes source clear, covering every assigned
store. `stage-close` stops after persisting the original handoff work; it does
not execute the handoff or clear the source. Recovery requires that exact staged
native work and verifies original admission, response and retained-acknowledgement
records. It reconciles the same qualified work rather than creating a replacement.
Written original evidence is flushed even if a qualified boundary returns an
error. Failed/partial outcome files are preserved for explicit recovery.

`original_clear_complete` describes the original work. `slot_idle` is a current
observation, not a lease: after a different generation uses the slot, an old close
must report it occupied and cannot clear that replacement. New admission must
still check actual actor state. Source/index/payload/control namespaces are
refused as output destinations; all control files use exclusive creation and
readback.

New retained references use the closer's canonical `objects/SHA256` layout.
Existing paths and immutable work are preserved. Older shared retainers can have
enough legacy `workflow/objects/SHA256/BYTES` paths that flattening them exceeds
the 128-path transition limit. The adapter exposes
`Budget: close-retained-layout-path-bound`; it neither chunks a transition nor
rewrites history. Operators must configure an already enrolled ready compatible
handoff retainer or plan a separately qualified migration. No actor is allocated
automatically. The original acknowledgement's retainer is preserved even when a
different handoff target is explicitly selected.

reported its original clear complete and the reused slot occupied; the replacement
