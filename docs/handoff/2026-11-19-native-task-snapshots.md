# Native retained task history across Git revisions

The opt-in `task_snapshots_native` fixture extends the
[task snapshot contracts](2026-11-19-task-snapshots.md) to actual retained native
comic data and a real parent/child Git revision. It clones only synthetic Git
history into a separate owned bare repository and adds an explicit English
candidate-planning revision. Existing source repositories and selected refs are
not modified. No native admission, publication, render, source close, selection
or scratch retirement is performed.

The fixture must establish all of these at its exact source/executable pins:

- The retained Spanish comic packet, native declaration and complete review
  copy/IDs stay identical in the new plan.
- The unaffected downstream consumer keeps its packet and canonical retained
  parent-result pin; only the affected branch advances its exact snapshot/key.
- Named record/annex bindings resolve from the new bare commit and native input
  bytes match the historical version. Mixed packet/declaration snapshots refuse.
- The native graph observes the original retained job, leaves the changed task
  unadmitted and its dependent blocked, and refuses retargeting the retained task.
- Restoring the original plan restores its exact frontier packets. Original
  claims and all original journal entries remain byte-identical.

This is a read-only retained-history/frontier qualification. It cannot prove
effectful adoption or rollback of an owned project profile, execution/retention
of the changed language task, real bilingual review, drawing substitution,
approval carry-forward or S5 episode scale. Those remain separate required work.
The new English prompt is synthetic planning data, not an approved translation.

Strict all-target Clippy with/without film passes before the run. The standard
66 native tests and 109 workflow/31 HTTP tests passed at the preceding production
source; this change adds an explicitly ignored existing-pool fixture only. Its
actual result and source/tool evidence will be recorded after execution.

Producer-applied editor and rights/provenance checks require unchanged IDs,
immutable lineage, separate language authority and no selection/release claim.
These checklists do not supply independent review or creative approval.
