# Composite source archives and child-owned input claims

The native adapter now represents exact Git inputs and retained-result origins in
one pinned composite declaration and immutable source archive. Upstream-only and
mixed inputs preserve logical origin before physical deduplication. Git records
still resolve against the exact declared commit; derived inputs identify exact
parent task/result/selector/artifact identities.

First admission must pass through the verified upstream admission wrapper. It
checks actual parent retained work/coverage/bytes and keeps parent owner fences
until child acceptance settles. Frozen origin metadata alone cannot create new
claims. The current scope is one exact declared reader/store/controller and shared
metadata/coordinator roots, with a separately enrolled child actor. Existing
16-actor and 128-change limits are enforced without batching around them.

After acceptance, the child's original work, activation, archive and positive
coverage authorize its input reads and resumable staging. Parent live contexts
are no longer an input-read dependency. Bare history can replace the original
checkout through an explicitly copied machine profile with unchanged portable
declaration. No current/latest selection is substituted.

The CLI adds `accept-upstream` and completed-original `recover-admission`.
Recovery verifies existing work rather than issuing effects under a fresh
identity. An idle/reused slot or uncertain/pending acceptance does not manufacture
a receipt; original-work reconciliation remains explicit. Receipt files use
exclusive creation and preserve partials on uncertainty. No slot, scratch,
capacity or payload release is authorized by these commands.

The manual intelligence result path can use composite sources. Comic worker
dispatch explicitly refuses them until input access is connected through full
tool replay and retained verification. Full issue assembly remains in the
completion ledger; input protection alone does not establish renderability.

Producer-applied comics, story/editorial, platform/audience and rights/provenance
checks preserve source/language identity and separate custody from creative,
translation, font, print and release decisions. Parent controls and staging remain
private. No provider call, render or public release is performed by admission.

Qualification covers 109 distinct tests: 63 unchanged shared tests carried forward
after verifying all 29 relevant source/Cargo file hashes, 37 default native tests,
and nine existing-store cases. The final boxed build passes all default native
tests, the complete owned-worker case and the expanded composite case. Seven
other native regressions passed before the allocation-only boxing correction;
they were not repeated for that correction. Both strict Clippy and formatting/
diff checks pass. Hosted CI has not run.

The composite fixture explicitly enrolls two parent and two child slots. It tests
upstream-only and mixed Git/upstream inputs, metadata-only admission/read refusal,
verified API and CLI acceptance, completed-original CLI recovery, and manual
child return through actual native retention. It then removes parent coverage in
the synthetic index without deleting payloads, makes the original checkout
unavailable and reopens/stages both children from serialized controls and bare
history. Repeated staging verifies immutable owned output. Test-only coverage
loss is not qualification of production close/release transactions. The default
suite also rejects a fabricated origin map as acceptance/recovery/read authority.
Private evidence, frozen tools and source manifests remain outside Git.

An initial lifecycle fixture used the wrong child attempt in its returned result;
the adapter correctly refused it, and the fixture was corrected. Regression work
also exposed Windows stack exhaustion in the deep owned-worker recovery path
after embedding a large claim guard in the input reader. The guard and internal
constructor argument are now boxed; ownership/fence lifetime is preserved while
reader stack size stays bounded. Diagnostics preserve process status, stderr and
the original fixture. The preserved failed operation was reconciled to retained
completion through its original frozen runtime's direct handoff interface, with
no replacement task/attempt and no claim or scratch release.
