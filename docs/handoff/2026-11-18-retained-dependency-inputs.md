# Explicit retained dependency inputs

`reel-workflow::upstream` binds a child input logical identity to an exact parent
task and named output or worker receipt. An additive optional task pin freezes
the canonical binding controls, so changing origin changes the child key even
when bytes match. Parent result digests bind attempts and receipt descriptors;
the complete parent artifact set, project and source commit must match the
child's declared dependency. Existing task encodings remain unchanged when the
new optional field is absent.

The native library reader verifies actual retained work, owner coverage, complete
result bytes and deterministic comic replay before allowing selected reads. It
shares retained-owner fences across parents and physical object gates across
selected byte-identical inputs, with logical verification preceding physical
reuse. It retains actual tool pins and owner fences for the session. Batch reads
currently require one exact native reader configuration and respect the existing
qualified Windows/native scope.

This read seam does not create child claims or admit resumable waiting work.
The Git-only source admission path explicitly refuses upstream-bound tasks.
Next work must freeze the composite source archive, protect all declared child
resources under the child's original operation and connect staging/worker/issue
assembly to that admission. Parent retention, cancellation, selection and scratch
retirement remain separate operations. No new cache engine is introduced.

Producer-applied comics editor, story/editorial, platform/audience and
rights/provenance checks preserve exact source identity and keep technical proof
separate from creative, translation, font, print and release authority. The map
addresses input origins; it does not invent comic reading order or modify canon.
Private parent controls and byte reads are not forwarded to providers.

Qualification: 63 shared tests, 36 default native tests and nine explicit
existing-store cases pass (108 distinct tests). Three new contract cases cover
equal-byte/different-origin binding, stale attempts/projects and explicit worker
receipt selection. Legacy v2 fingerprint checks still pass. Both dependency
graphs pass strict Clippy; formatting and diff checks pass. Hosted CI has not run.

The expanded two-job native fixture first stages its original batch, retains both
results under one target actor, then reads two logically distinct inputs with
identical native bytes through one session. It refuses undeclared identities and
insufficient read allowances, and confirms that Git-only child admission refuses
the upstream declaration. That targeted case passed before the remaining eight
native regressions; the lifecycle executable's byte hash was unchanged between
runs. Test-only comic evidence was added to the latter run.

The selected comic-part fixture additionally reads its actual worker receipt and
reading PDF through this adapter after the original authored source/render folders
are removed and Git history is bare. The unselected page stays unprotected.
Existing comic restoration/fresh-edit and owned-worker recovery tests pass.
This proves the bounded borrowed read seam, not complete issue assembly or
durable child claims. Frozen runtime, private controls, logs and source manifest
remain outside Git.
