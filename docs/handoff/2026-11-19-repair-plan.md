# Candidate repair plans from checked findings

`reel-workflow::repair::materialize` now turns an exact-pin repair and revision
request into a checked candidate `Plan`. The same operation serves film and
comic graphs. It applies the declared before/after artifact replacements to
matching task inputs and matching producer publication, request, runtime,
auxiliary runtime, part-plan and upstream-binding references. It preserves
task IDs, prompts, language, output contracts, producer choices and DAG edges
except for explicitly edited artifact pointers.

```text
reel-workflow revise-repair PLAN COPY REPORT REPAIR REVISION NEW_PLAN
reel-workflow-native export-repair-plan PACKET NATIVE_PROFILE ADMISSION_PROFILE RECEIPT RESULT ACK PLAN REPAIR REVISION NEW_PLAN --apply
```

Both commands exclusively write a normal `reel.workflow-plan.v2` document,
which existing plan consumers can read directly. Existing files and partial
failed writes are preserved. The Rust API additionally returns the plan hash,
revision hash and repair impact. `plan-repair` remains available for separately
exporting the impact document. These exports are private controls.

The native command first reopens the retained structured report under its
original native proof. An unrelated or stale report, baseline or finding refuses
before creating the output. The local command checks supplied report/copy
contracts only; it does not establish their custody or actual viewing.

Revision JSON has schema `reel.workflow-repair-revision.v1`, a new exact
`source_commit`, and `native_inputs`, a map from task ID to before/after
declaration descriptors. The map must cover exactly every task that already
has a native declaration, including creatively unaffected tasks: native
declarations bind a source commit. Each old declaration must match exactly,
and its replacement must preserve logical ID and change its pin. A conflicting
replacement in the repair edit list refuses. The compiler does not invent
declaration bytes, rewrite control JSON, create a commit or verify that the
proposed new snapshot exists. Native freezing/admission must check it later.

Repair impact now includes references outside ordinary task inputs, such as
renderer and auxiliary executable pins. Their exact consumers and downstream
tasks must rebuild too. A language-local input edit preserves other languages'
task definitions; shared art/runtime edits can affect multiple editions.
The impact retains the full contextual review requirement and language set.

## Execution boundary

This is a candidate plan, not an applied selection or a completed fix. A new
source commit changes packet identity, including for otherwise unchanged tasks.
Never transplant old packets, native declarations or completion receipts into
the new run. Native consumers still require exact new committed inputs and
qualified admission. Dependency consumers must be expanded/frozen against the
new retained parent results; this compiler does not predict generated bytes or
replace stale embedded parent pins inside a control asset. Updated control
assets must be explicitly supplied as edits or produced by the existing derived
control/expansion flow.

The replacement descriptors do not prove candidate bytes exist or are retained.
This command does not execute an LLM, renderer or script, send a tracker message,
release old claims, select a master, resolve a finding or close an issue.
Automatic corrected-edition execution and evidenced closure remain open.

## Producer checklist review

Applied editor, comics-editor and rights/provenance lenses. A local line fix
still requires neighboring/page/full-issue or full-film contextual review;
preserving English task definitions does not approve Spanish wording. No
creative, translation, voice/font, print or release decision follows from
materializing a technically valid plan. Historical inputs and plans stay intact.
