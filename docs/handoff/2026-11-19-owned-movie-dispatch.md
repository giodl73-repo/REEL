# Owned movie production dispatch

With the Windows `film` feature, deterministic FilmRender tasks now use the
existing owned worker dispatch. Preparation requires the original pinned worker
runtime, exact installed auxiliary programs and an explicit native-profile movie
verifier. It reserves render workspace, two result/evidence copies and existing
control overhead; metadata validation alone never admits that production space.

The worker creates its packet directory under the original owned intent, runs
the contained renderer and binds native candidate paths without flattening the
delivery layout. Generic materialization adopts the exact existing render bytes
and writes the separate task/worker controls. Source/object gates drop before
managed candidate ingress and retained-owner effects. Journal completion follows
actual retained proof; redispatch of Retained work checks history rather than
rendering a new movie.

If production finished before generic materialization was recorded, recovery
can adopt only the completed original request/outcome with identical installed
paths, input locators, tools, limits and declared outputs. Existing worker receipt
bytes must match. Foreign entries, missing/failed outcomes and partial media stop
with preserved scratch; they never trigger a replacement render or new attempt.
Independent return/native primary comparison still checks adopted candidates
before publication/completion. Recovery of a missing outcome or incomplete render
remains separate work and is not inferred from available movie bytes.

Legacy worker modes retain their reservation and serialization rules. No admission
projection changes reinterpret previously accepted movie jobs. Historical producer
runtime pins are not upgraded; automatic production needs a task explicitly bound
to a runtime that implements this capability. Without `film`, dispatch refuses.
Selection, job-slot close/reuse and scratch/capacity retirement remain explicit.
