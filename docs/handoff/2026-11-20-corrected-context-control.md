The opt-in `corrected_context_control_native` fixture consumes the certified
producer-bound review preflight without changing its task, source, attempt,
operation or selected 3fa runtime. It first verifies all certificate pins, the
actual original Index checkpoint and the unrelated Waiting claim.

Before effects, it records a finite 1,024-object / 1 GiB new-job retained-owner
policy and the original operation identity. Original issue slot return uses the
exact already-retained recovery policy, an explicit v2 close ticket and staged
WorkRef recovery. Replay through the original 264efd runtime must leave Index
unchanged. Only then can one new control admission acquire the actual retained
parent closure and dispatch the pinned worker once. Source budgets, 128-path and
16-actor bounds remain unchanged. Failure preserves the original job for exact
reconciliation; it is not permission to readmit under a fresh identity.

Completion requires retained acknowledgement and native producer proof, exact
equality of request/copy/manifest with preflight, the original producer witness,
historical parent and Waiting proofs, and completed replay without Index or owned
worker-result changes. Scratch remains preserved.

The fixture then declares the report using the actual retained control outputs
and the unique original opening/closing producers for its two reading images.
Only the publication record stays in its fixed source subset. The exact report
packet, plan, source, parents, upstream bindings and declared-input preview are
saved separately. This is a report preflight: no report is admitted, retained,
generated by a provider or accepted as a viewing/creative review. Finding closure,
selection, creative approval, release, real BBJ/S5 scale and production-profile
adoption/rollback remain separate gates.
