# Native movie candidates and retained verification

Native profiles optionally declare `movie_verifier`: exact verifier runtime,
FFmpeg/FFprobe bindings and an existing owned scratch/capacity profile. None is
omitted from serialization, preserving legacy profile bytes. These explicit
read-only machine bindings do not retarget historical producer tickets or change
portable task/source selection. Film support remains an optional Windows feature.

The generic response verifier now routes FilmRender returns through full guarded
media and primary-master comparison before candidate registration/publication.
Retained/pre-retention proof resolves every supplied result and worker-receipt
object through the existing qualified native reader and ReadCache, preserving
exact gates/paths and reusing input/output objects with identical byte identity.
No second cache engine, pool discovery or selected-record fallback is introduced.

Native proof checks original task/attempt, exact artifact/canonical worker-receipt
correspondence and producer evidence before verifying decoded media and primary
YUV/RGB/PCM. Actual output locators come from native objects, not historical worker
or returned-file directories. Retention still independently checks original work,
actual retained actor coverage and all assigned stores before issuing live proof.

Read-only comparison scratch uses existing owned directory/capacity primitives.
A durable private controller records original context, directory identity/intent
and reservation before execution. Context pins source/result/current locators,
tools and limits. Repeated successful verification reopens that exact ticket and
reruns the same read-only request; it never trusts a previous success as a result
cache. Prior request/outcome bytes cannot be replaced. Partial, failed, foreign
or changed checkpoints refuse and preserve original scratch/capacity. Controller
preparation crash reconciliation is not yet qualified; an incomplete controller
stops rather than allocating a replacement reservation.

Source/object gates are dropped before new managed native retention effects,
following the existing lifecycle boundary. Claims do not expire, and returning
from a check does not release reservations or retire scratch. Frame/process and
existing 128 MiB result/128-path/actor limits remain; no implicit splitting or
limit increase occurs. Automatic movie rendering dispatch remains gated pending
owned worker production/recovery integration.

The synthetic qualification uses the original admitted movie, ingests the exact
candidate through managed response interfaces, retains it, verifies it repeatedly,
then verifies using bare Git history while return paths are absent and original
worker media is held unreadable. Original native history and scratch are preserved.
Actual evidence will be recorded after execution.

Producer-applied editor and rights/provenance review: independent source clocks
and primary comparison reject counterfeit media; private evidence remains private.
Technical proof is separate from task completion, creative/translation/voice/font
approval, selection and release. These are checklist findings, not human approval.
