# Large native result lifecycle qualification

This fixture targets the remaining native publication/retained-result boundary
using the already reserved 3,600,000,001-byte synthetic regular file. It is a
generic unselected byte-ingress qualification, not film rendering, creative
review, episode composition or consumer adoption.

## Original operation and bounds

The fixture requires an explicitly named existing retained synthetic movie job,
its original profile/journal/acknowledgement and an explicitly frozen release
CLI. It verifies current original admission and reads every named existing input
before changing job state. The original movie records/runtime/profile are not
retargeted. Its source slot may close only through the qualified retained-owner
handoff and close transaction. Every retained reference remains preserved.

One replacement job reuses the same declared Index/slot and existing exact-commit
inputs. A v2 snapshot declares 64 MiB input/per-object allowances, an 8 GiB full
projection and a 4 GiB return total/object allowance with 300-second local
verification. The native reader explicitly allows 4 GiB. The result selects the
known synthetic bytes as an unselected `application/octet-stream` candidate,
with no claimed model/provider. No current or historical production selection
changes, and no new cache, store, actor enrollment or media is created.

The root records the original operation, task/attempt, exact source/profile,
new admission, source close ticket/pin/outcome, staged candidate WorkRef and
return identity before ingestion. Managed handoff import must protect outputs,
publish/reopen native bytes, acknowledge retained ownership and record Retained
journal completion. Read-only retained verification and return-free journal
replay then recheck that same result and acknowledgement. The qualified Tig
publisher's fixed 30-second transfer/reopen bounds remain unchanged.

## Recovery and evidence boundary

The fixture and all scratch are preserved on success or failure. A partial
publication or missing reply is not evidence that the first attempt had no
effect. The separate resume entry point uses only the original saved profile,
runtime, journal and return body; it does not close/re-admit a source or allocate
a fresh operation. Command observations use bounded new no-clobber filenames;
matching acknowledgement/completion files are idempotent and conflicting bytes
refuse. Earlier-stage interruption requires inspecting the original close/work
handles before any continuation, rather than restarting the fresh fixture.

An ordinary compile or a local 3.6 GB hash test does not establish this lifecycle.
Even a successful generic result fixture would
leave large native child inputs, v2 film producer/verification, 600-resource
composition, full bilingual delivery and owned project adoption/rollback open.
The producer rights/provenance checklist keeps technical byte retention separate
from source-use, voice/likeness, creative approval, selection and release. No
actual S4/S5 production job, media, recording or approval is changed.
