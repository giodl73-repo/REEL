# Workflow response ingress — producer handoff

The isolated REEL workflow branch now records external provider responses under
stable task/attempt identity, protects their complete artifact set and ingests
exact unselected native bytes. It adds `stage-response`, `register-response` and
`ingest-response`, each with an explicit `--apply` and new private candidate
receipt destination. The generic adapter accepts direct/manual intelligence
results; deterministic tool/comic receipt integration remains open.

Staging verifies the complete explicit file set, then records original SDK work
without admitting output claims. Registration additionally executes that work,
extends the active job envelope and checks positive protection. Ingestion uses
the existing Rust native publisher and requires every object to reopen verified.
Original selection, policy, activation, current references and source root remain
protected. No new cache engine, slot allocation or publisher CLI stderr parsing
is introduced. Exact vendored SDK and lifecycle module pins remain unchanged.

The logical key excludes content and activation so another response body,
logical artifact identity, provenance claim or generation cannot create a second
registration for the same task/attempt. Immutable evidence binds the original
admission, store and complete returned result. Repeated imports return the same
WorkRef. Recovery reconciles only matching original admitted work, including a
crash after native Prepare. A changed result leaves that pending operation alone.
The original returned files must be preserved and verified on every retry; a
lost candidate receipt is reconciled into a NEW receipt destination, never a new
attempt. No cleanup follows an uncertain result.

Bounds: existing Windows/NTFS cooperating native scope; one explicit enrolled
store; 32 returned artifacts; 128 MiB total; one 64 KiB native metadata evidence
node; existing 128 changed-path and 1 GiB resource envelope limits. File paths
must be portable relative mappings under an existing owned directory outside
managed roots. Active directory/file/tool guards remain held during effects.
No package extraction, provider execution, hydration, upload or selection occurs.

Three new default fixtures exercise real isolated metadata journals and guarded
return files, including identity conflicts, corruption, invalid mappings and
fault-injected native Prepare recovery. One explicit native fixture publishes
only a synthetic response into the existing synthetic test pool, verifies native
byte reopening and repeats ingestion across separate CLI processes. Original
positive input/output claims and returned files remain intact. All 28 default
native tests and three explicitly invoked native fixtures pass; the 249 original
SDK/lifecycle source pins match. Strict native Clippy, root/native fmt and diff
checks pass locally. Shared workflow/publication/capacity sources are unchanged;
hosted CI has not run. Evidence and frozen tools remain outside Git.

This is bounded response registration/ingress, not completed W2 retained-result
qualification. Candidate publication is weaker than retained-owner registration.
All CLI results leave retained-owner acknowledgement, task completion, selection,
scratch retirement authorization and input release false. The next step is real
retained-owner acknowledgement/readback followed by connecting the native
`handoff::Lifecycle` port. Comic worker receipt/source validation, expected-baseline
selection, actor close and guarded scratch/capacity retirement remain open.
No production film/comic project or public release was adopted.
