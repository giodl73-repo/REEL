# Offline inventory-review checkpoint

`tier-review` groups a fresh saved plan with all-consumer protections into a
private offline view. `tier-request` validates an exact owner's block decision
and prepares the existing native dry-run request. It performs no cache mutation.
See ../asset-tier-review-v1.md for budgets, contract and explicit limitations.

Executed locally on Windows: 91 asset-crate tests (90 unit, one actual executable
regression), scoped Clippy, release build, formatting, role structure and whitespace
checks. Nine new tests include cross-consumer changes while the primary plan stays
fresh and the real decision-to-native-verification route. Inputs are synthetic.
Private production proofs, raw inventories and browser evidence belong upstream.

`manager-review` recreates a review from a portable project file, a registered
cached inventory and Git's current worktree registry. It starts with no chosen
hashes and freezes source declarations through request preparation and guarded
application. A new/undeclared lane holds instead of silently losing coverage.

Producer-applied review: observation is not backup integrity, metadata freshness
is not current physical state, block choice is not application, and source pin
adoption is separate from replacing an executable. Scope/decision mutation and
stale protections fail closed. No private hashes, roots, media or reports are
included in public fixtures. No human or publication approval is inferred.

Urgent cold-copy extension: explicit policy-named retained cold tier, exact
existing-object verification and durable cold custody before unlink. No archive
crawl, payload copy, last-copy retirement or relaxed job/selection safeguards.
Producer-applied storage/provenance review: unknown provenance is preserved,
active registration is distinct from cold custody, public fixtures remain
synthetic. Tests cover cold dry-run, missing/corrupt copy, history mismatch,
receipt publication failure and successful/idempotent Windows cold removal.

Cold concurrency regression: unrelated live reservations and newly registered
other objects allow removal; registering the exact candidate immediately before
unlink holds it. 97 Windows tests pass (96 unit plus one executable), scoped
Clippy and release build. Metadata transaction locking remains short and exact.

Explicit verified-index reuse adds hash-bound prior cold verification and an
optional exact unchanged source identity/mtime proof. It does not equate a
census with integrity evidence. Default full hashing remains unchanged.
101 Windows tests pass (100 unit plus executable), Clippy and release build.

Exact hash-indexed aliases in explicitly requested cache namespaces preserve
physical identity checks and unknown-link holds. A bounded two-second cold
transaction wait avoids aborting on unrelated short writers; reservations are
untouched. 103 Windows tests pass (102 unit plus executable), scoped Clippy and
release build. Interruption tests retain original CAS-first unlink order.
