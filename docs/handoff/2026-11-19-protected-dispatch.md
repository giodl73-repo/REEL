# Protected recipe dispatch

```text
reel-workflow-native dispatch-task PLAN BINDINGS TASK CONFIG PRIVATE_DIRECTORY --apply
```

`reel.workflow-dispatch.v1` configuration contains `input_staging` and optional
`worker_staging` profiles using the existing explicit capacity policy. A manual
intelligence task has no worker profile. A deterministic task requires one and
must use the existing qualified comic renderer, issue control or issue assembler
in its original pinned lifecycle executable. Returned text is never executed as
a command. Provider calls remain a separate integration.

Dispatch validates the original plan, job, current frontier, runtime and control
namespaces, then creates an immutable intent bound to the actual directory
identity. Native/source/job controls cannot be scratch. It persists the original
input ticket and its exact pin, a staged run-binding snapshot and protected ready
batch. Deterministic dispatch persists the original worker ticket/pin and calls
the existing worker, whose completion requires actual retained publication proof.
Manual dispatch leaves a Waiting job and returns its protected prompt-batch pin.

Exclusive control creation, flush/readback and a scoped dispatch fence preserve
partial files. Replays reuse original tickets, owned workspaces, capacity records
and WorkRefs. Missing bytes, changed controls and uncertain ticket preparation do
not create a replacement attempt or overwrite evidence. If ticket creation was
interrupted after reservation, the partial ticket and conservative reservation
remain for explicit recovery. Native pending worker ingress reconciles the same
materialized result through the existing worker. Manual pending ingress still
requires its original returned response through the existing import command.

Recipe steps can opt in with an additive `execution` field containing this
configuration. Omitted fields retain admission-only behavior and serialization.
The runner checkpoints adoption before dispatch. It resumes execution from each
task's original adoption snapshot, so later plan growth cannot retarget an old
batch. Retained and cancelled jobs are not restarted. Already prepared manual
handoffs do not consume the resumed-effect budget or starve later tasks. One call
permits up to `LIMIT` resumed task effects and `LIMIT` new admissions/dispatches.
Worker completion may unlock another recipe wave in the same invocation.

The runner now reserves a full checkpoint control allowance before further
admission; new checkpoints remain within its 32 MiB replay-history bound.

Metadata/claim tests cover missing native bytes, unchanged-index retries, one
preserved staging workspace/ticket, changed configuration, partial controls,
operation-mode refusal and runner recovery after dispatch failure. Existing-pool
qualification is pending for automatic multi-wave manual handoffs and one-command
comic staging/render/retention followed by editable historical restoration.

Dispatch does not close actors, retire scratch/capacity, select a candidate or
grant creative, translation, font/print or release approval. Producer-applied
recovery/custody and provenance checklists are separate from independent review.
