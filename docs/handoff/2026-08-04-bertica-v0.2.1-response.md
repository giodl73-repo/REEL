# REEL response to BERTICA v0.2.1 requests

REEL implemented the full follow-up as CLI version 0.2.1 while retaining scene
manifest version `reel.manifest.v0.2` unchanged.

| Request | Delivered contract |
|---|---|
| Native episodic series | `reel.series.v0.1`, child path/work/hash/state references, five reports/commands, ordering, source, runtime, dependency, privacy, platform, speaker, continuity, and release gates. |
| Scene-to-episode composition | Atomic `episode-compose` packet with referenced child hashes, continuous captions, protected-pause identity, lineage, coverage, duration, and attributed cards/credits/bridges. |
| Caption/cue import | `cue-import-srt` with millisecond parsing, mapping or global speaker/source assignment, shot overlap, lineage, and exact caption reproduction. |
| Shared continuity | `reel.continuity.v0.1`, hashed external references, scene overlays, ordinary validation, and privacy-safe provider resolution. |

## Existing capabilities reused

Scene timing states, speaker cues, protected pauses, source coverage, provider
egress policy, variant lineage, principal findings, and long-still checks remain
owned by v0.2 child manifests. The series layer references those facts and
validates compatibility; it does not copy or reinterpret them.

## Migration

The five original and all later BERTICA scene manifests require no migration.
BERTICA creates a `reel.series.v0.1` index whose child entries point to the
preferred existing manifest or conform packet and record its work ID, SHA-256,
accepted timing/review states, expected duration, source completeness, privacy
state, platform requirements, and speaker constraints.

Existing SRT-only timed proofs can optionally become new v0.2 derivatives with
`cue-import-srt`. Their source manifests remain untouched.

## BERTICA consumption contract

```powershell
reel series-validate production/reel/series/el-camino-v1.yaml --output json
reel series-plan production/reel/series/el-camino-v1.yaml --output json
reel series-coverage production/reel/series/el-camino-v1.yaml --output json
reel series-review-queue production/reel/series/el-camino-v1.yaml --output json
reel episode-compose production/reel/series/el-camino-v1.yaml S2E02 `
  --output-dir production/reel/composed/S2E02-v1 --output json
```

BERTICA should consume the atomic episode packet's `manifest.yaml`,
`captions.srt`, `lineage.json`, `coverage.json`, and `duration.json`. It remains
the owner of canon, consent, private assets, historical interpretation, and all
principal decisions.

No manuscript text, photograph, source voice, or binary render was copied into
REEL. The automated 50-episode acceptance slate and all continuity entities use
sanitized synthetic material.
