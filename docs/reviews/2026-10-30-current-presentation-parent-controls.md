# Current presentation parent controls

An authored conform can still name an older opening after the current Tig output
selection changes. A parent must compile that current selection into its actual
render controls, rather than stop at a stale-reference diagnostic or rewrite a
historical production receipt.

The current-component factory now derives presentation controls from one source
snapshot and its sealed primary-reference proofs. It retains the authored conform
as layout/baseline evidence and generates the effective manifest in memory.
Selected paths come from the proof's held byte guards. The existing native
assembly kernel consumes the current evidence under its own schema, independently
of the old adoption receipt. Parent/child source and runtime ownership remain
required before and after assembly.

Generated control bodies, their identity records and bounded pages use existing
Tig Merkle trees and metadata nodes. No node exceeds the metadata provider's
64 KiB limit. Full body identities remain exact; the job declares the physical
page/tree obligations, finishes the provider, and verifies every generated node
on readback. Nothing is added to authored Git state or a new cache namespace.
Control bodies are bounded to 4 MiB each and 16 MiB total.

Producer-applied editing, sound and provenance checklists require exact component
scope, matched frame/sample clocks and PCM, immutable original receipts and
separation of technical evidence from approval. The implementation uses these
requirements; this is not independent review or release authority.

The synthetic fixture uses a valid ordered-unit parent and a genuine current
presentation proof. With Git/working records offline, it compiles an intentionally
stale movie reference, assembles the selected native component, checks decoded
parent content/timestamps, rejects missing generated metadata, and refuses a
withdrawn child owner. The obsolete movie is absent from required resources.
A separate 150,000-byte framing case reopens bounded existing nodes and restores
the exact original body.

Open work remains: changed-scene controls, invocation-content/source-text binding,
bounded parent CLI/scheduler integration, complete child handoff/custody and actual
project cutover. Native source-owned presentations currently require empty parent
content overrides. Those gaps cannot be promoted to success by this fixture.
Exact final local and hosted qualification is required before adoption.
