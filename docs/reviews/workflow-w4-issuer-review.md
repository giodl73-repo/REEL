# Film issuer role review

Author-applied Editor, Platform and Audience, and Rights and Provenance
checklists. These are not independent review or creative/production approval.

- Editor: issue text preserves the exact exported frame/target subject. This
  transport adds no clock conversion, cue edit, new drawing or language fallback.
- Platform: private exported API bodies are accepted through the existing owned
  transport. Terminal results omit repository/text; the private receipt retains
  the exact issue reference. UI navigation remains separate work.
- Rights/Provenance: sending text requires its pinned request and explicit apply.
  No attached media or automatically discovered file leaves the machine. The
  destination is explicit; issue text itself contains private project identities.
  Technical response acceptance grants no review, rights or release authority.
- Recovery: note refinement keeps one logical operation. A response can be lost
  after remote creation; absence of a local receipt is never proof that no issue
  exists. Preserve the original registry and evidence. Remote uncertain-outcome
  reconciliation/adoption is still an open gate; no fresh-ID retry is supplied.

The existing HTTP owner, capacity and captured-response machinery is reused.
No registry/cache engine, dependency update, native claim behavior, provider
execution, repair, selection or profile adoption is added. Synthetic loopback
receipts explicitly distinguish simulation from actual GitHub submission.

Run scoped strict Clippy and all HTTP tests on the exact PR head. Local
qualification is synthetic only; hosted Windows/Linux qualification remains
required before merge. Production issues are not created as test evidence.
