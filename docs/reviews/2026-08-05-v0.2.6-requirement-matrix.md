# v0.2.6 privacy-safe receipt requirement matrix

| Learning | Implementation | Verification |
| --- | --- | --- |
| Full artifact reports contain private local paths by design | `animatic-receipt` emits a separate typed path-free derivative | Unit serialization scan and real CLI receipt scan |
| A share derivative must not bypass verification | Receipt generation calls `animatic-check` first | Real sanitized end-to-end command |
| The receipt must still bind to exact evidence | Source artifact SHA-256, verified video SHA-256, environment fingerprint | Real receipt values compared with the source artifact |
| Consumer identifiers can leak even without filesystem paths | Omit work/title, input IDs/hashes, shot IDs, and executable strings; bucket unknown kinds as `other` | Typed schema review and forbidden-token assertions |
| Failed or repeated publication must be atomic | Temporary sibling file plus no-clobber persistence | CLI overwrite test preserves original bytes |
| The expanded command graph exceeded Windows' 1 MiB main-thread stack | Parse and dispatch on a named 8 MiB CLI worker; keep the subcommand enum boxed | Windows production CLI regression suite |
| Sharing does not equal approval | Receipt has verification state only and no approval field | Documentation and Story/Public Surface role review |
| Consumer schema stability | CLI 0.2.6; `reel.manifest.v0.2` remains unchanged | Full regression suite and existing fixtures |
