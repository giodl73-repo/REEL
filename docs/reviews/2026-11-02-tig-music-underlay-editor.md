# Tig-backed exact-text underlay authoring

Producer-applied role review; no independent, listening or creative approval.

The lyric/vocal adaptation checklist requires separate exact canonical/as-sung
subjects, selected-layer language and kind, exact UTF-8 offsets and source order.
The adapter consumes only the explicit model binding and retains both source
locks. It never corrects, normalizes, translates or synthesizes text or voice.
Changed lyric bytes refuse against the model's observed hash.

Music reconstruction and score/arrangement checks preserve all notes, source and
analysis references. The existing native underlay validator checks the proposed
source map; musical-source validation, signal decoding and listening remain open.
Unreviewed proposals require the lyric/vocal editor role and inherit no authority
decision. A note edit can follow an underlay edit and vice versa; each predecessor
record remains an exact lineage subject rather than an approval transfer.

Rights/provenance checks keep the model and lyric reader guards live, destination
outside providers, private text only in local session/artifact files and stdout
limited to counts/flags. No server, network, publication, cache initialization,
production binding, Git write or eviction is introduced.

Regression coverage includes original local underlay behavior, native paired
model/text editing, unrelated commit coexistence, stale text annotation, wrong
language/kind, missing binding, changed selected bytes/definition and the actual
CLI's bounded summary. Full music dependency validation and managed adoption
remain separate acceptance work.
