# Original-song runtime diagnosis

A private managed repair returned native child exit `0xC0000005` without retaining
a declared raw patch. Basic library imports, a small CUDA operation and a contained
synthetic child using the installed Python passed. None established the failing
model phase or the cause, and another unchanged generation attempt would not
resolve that uncertainty.

The optional `diagnose-runtime` entry retains the same held original inputs,
installed read set and bounded quiet child execution. Its backend mode returns
after model initialization, before generation parameter construction, any patch
call or final materialization. Fixed, synced phase markers survive native death;
bounded Windows failures additionally report peak committed Job Object memory
without exposing source text or creating an unbounded process log. Existing model
parameters and every capacity/process/time policy stay unchanged.

Producer-applied review uses reconstruction for original/conditioning byte
correspondence; sound/editing to keep initialization distinct from acoustic or
beat acceptance; lyric review to keep supplied and performed words distinct; and
provenance to preserve private restrictions, output pins and separate authority.
This is technical review, not independent or creative approval.

Synthetic tests reject a runtime receipt that claims generation, generated files,
an incomplete or extra phase sequence and failed initialization. Python tests
make every generation constructor/call fatal and prove the runtime route returns
without reaching them, while testing bounded/no-clobber progress and exception
propagation without logging private text. The explicitly enrolled Windows child
exercises both modes with synthetic audio and attempted input writes; the Job
Object fixture checks the original exit code, numeric memory accounting, process
cleanup and existing resource bounds. No actual runtime success or repaired-song
delivery is inferred from these synthetic cases.
