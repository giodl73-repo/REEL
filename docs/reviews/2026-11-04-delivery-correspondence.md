# Pinned delivery correspondence tables

An external receipt can associate many exact observed paths with stable provider
IDs. The delivery auditor now consumes such an explicitly pinned table through
one mapping instead of duplicating its rows in the bounded profile. Existing
prefix mappings retain their behavior and limits.

The table is private metadata, not a replacement publication assertion. Every
asset still binds its definition/schema and original subject/target receipt
through Tig. No media, provider request, namespace scan or mutation is added.
The table pin remains part of the private profile identity. Matches retain their
existing length-only interpretation, with remote currency, custody, approval
and eviction false.

Producer-applied rights/provenance review requires unchanged source metadata,
explicit field pointers, exact scoped identity and no inferred authority. The
platform/audience review keeps paths and IDs in the private report while stdout
contains only counts/flags. Both require rejection of ambiguous correspondence,
explicit Windows separator conversion and no case or basename guesses. This is
a checklist application, not independent or human approval.

The integration fixture exercises a committed source, a 147-row external table
larger than the native profile budget, and missing payload objects. It preserves
unmatched lookalike paths and checks refusal before output for corrupt pins,
duplicate keys/paths/targets, missing fields, traversal, prefix escape, invalid
pointers and mixed mapping modes. Actual project replay and required hosted
qualification remain separate from these synthetic checks.
