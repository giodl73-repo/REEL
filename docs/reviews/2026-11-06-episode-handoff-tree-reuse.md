# Reuse retained episode trees during metadata handoff

A completed episode could fail its final metadata handoff when the node store
had room for a small wrapper but not another flat index of all protected
resources. The film and original temporary source claims remained retained.

New handoffs preserve each complete result, input and temporary tree beneath
distinct context paths. Canonical directory nodes retain their identities, so
the store reuses them. Explicit root-resource pins preserve the original
protection obligations. The unique resource objects and logical byte sum must
equal the original bounded closure before any packet is published. Complete
readback and root adoption still precede temporary-source withdrawal.

The header records the new layout. Recovery of a pending preparation reads its
layout and reconstructs the exact original selection. Legacy flat packets remain
supported; unknown layouts fail. The native render, source selections, metadata
configuration, capacity guards and approval gates do not change.

The bounded-node fixture retains the same 1,001 unique resources twice beneath
different prefixes with fewer than 32 new metadata nodes. Flattening that same
closure exceeds the unchanged 32-node allowance. Actual journal fixtures cover
interrupted preparation, exact pending selection, legacy pending recovery,
foreign preparations, missing reports, resource-budget refusal, failed-worker
diagnostics, adoption-before-withdrawal and repeated completion.

Producer-applied provenance review checks complete resource preservation and
immutable source identities. Editing and sound review preserve the successful
worker's frame, PCM and timestamp checks; handoff recovery performs no media
processing. Platform review makes no playback or delivery claim. These are
technical checklist findings, not independent review or human approval.

Local and hosted qualification results must be checked for the exact commit
before using the runtime for a private recovery. Raw operational evidence and
private source identities remain in the producing repository's existing cache.
