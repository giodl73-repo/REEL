# Scene correspondence for managed episode capture

Before capturing an episode job, selected scene masters must be compared with
current native source recipes rather than a status string or unchanged scene JSON
pin. The new gate reuses opaque `JobPlan` and `ReplayedClaim` capabilities from
the existing native APIs. It independently binds the selected subject in the
current view, enforces scene/definition/language/kind/checkpoint identity, checks
the exact original claim subject and compares recipe correspondence. It never
reads primary/output bytes, promotes status or grants execution/retirement.

The assembly-wide gate recomputes the logical plan and enforces exact native scene
coverage. Its non-deserializable per-scene results retain exact current record,
source, selected subject, claim and recipe pins; a report or mutable public Plan
cannot substitute for them. Every declared component-output type is excluded
from native primary/control definition sets. Presentation acceptance and full
managed context/resources/custody still need their separate gates.

The generated episode fixture replays an original native claim from its retained
metadata, derives fresh native jobs against current Git views, and checks that
status-only edits preserve correspondence while another output, substituted
selected bytes, or a changed primary cel refuses. Changed cel/master bodies are
deliberately absent: detection must occur before any body lookup. Returning to
the old source view restores correspondence. A logical episode/assembly points
to four independently versioned scene outputs; exact complete proof coverage
passes, missing/wrong coverage fails, and a changed checkpoint invalidates old
capabilities. Only two bounded episode/conform control bodies are read during
the aggregate check. No actual project media/cache is involved.

Editor and Sound Designer lenses require current consumed-source correspondence
without introducing a render per authoring commit. Rights/Provenance requires
independent original producer admission and separates unsigned recipe claims
from execution, byte verification, creative selection and delivery. These are
producer checklist findings, not independent or human approval. Complete episode
job capture/execution, presentation currency and project cutover remain open.

Local qualification passes: eight logical episode tests (33.29s), both complete
generated episode/cache fixtures (113.28s), warnings-denied locked all-target/
all-feature Clippy (50.75s), formatting and diff checks. The earlier pass before
the complete declarative aggregate fixture also passed eight episode tests,
both lifecycle fixtures and 205 library tests (nine explicit external cases
ignored). Hosted exact-head Linux/Windows/FFmpeg qualification remains required.

Next capture obligation: component outputs need explicitly admitted pre-execution
resource protection under a composition/evidence role. Do not put rendered scene
masters in Primary or Runtime to fit the existing single-scene job envelope.
Keep original/current claims and source/control roots separate from actual output
availability. Generated-primary eligibility and full presentation currency also
remain separate; a native scene recipe match cannot certify those layers. This
gate is a prerequisite for the complete managed episode job, not its replacement.
