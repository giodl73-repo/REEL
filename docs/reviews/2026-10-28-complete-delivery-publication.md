# Publish and adopt complete native delivery output resources

Parent source55817645e3f60ff01c02ec8a92f4ad3fd138d603. This extends the existing
checked native candidate publication port, shared CAS publisher and protected job
protocol. No second cache implementation, payload copy loop or new pointer format
is introduced. Publication is an explicit caller choice with a distinct object/
byte budget; mapped-payload publication remains available for compact workflows.

Every named native output is reverified before any provider mutation, alongside
all capabilities and the deduplicated complete budget (including receipt/claim).
The source receipt retains the exact original pins. Stable per-name request keys
preserve operation conflicts and exact retry. Complete payloads are acknowledged
before receipt and claim. Errors may leave acknowledged prefixes, not a completed
bundle result; source bytes remain caller-owned until handoff obligations finish.

Successful complete publication exposes the exact output map. Protected native
jobs include those objects as named Evidence in output freeze/readback/adoption,
separate from canonical primary inputs and without inventing complete global
claim coverage. The upstream Tig total-entry budget extension is required for
large evidence sets; current vendored code retains its old count limit until
that source is qualified and integrated.

The generated cached-episode fixture now uses managed complete publication for
every unit. It has no manual output-list publication loop. The native job result
readback must contain every complete output in Evidence; subsequent cache-only
scene and episode checks run with original render directories unavailable. One
output remains history-only through assembly. Failure cases cover zero/insufficient
budgets, unsupported acknowledgement, changed unmapped output with zero provider
visits, failure at receipt publication after a verified prefix, and exact replay.

Producer-applied Editor/Sound Designer checklists retain the existing independent
frame/PCM checks. Rights/Provenance keeps generated media only, no upload, exact
context/recipe/subject pins and separate technical versus creative authority.
These are not independent or human signoffs. This API does not grant durable
custody, eviction authority, a complete production runtime closure or real project
readiness. Full complete-publication CLI integration and cache-backed presentation
segments remain open. Hosted exact-head qualification and prerequisite integration
are required before merge; operational raw data stays outside Git.
