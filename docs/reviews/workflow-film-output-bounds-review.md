# Film output budget routing

Author-applied Editor, Sound Designer, Platform and Audience, and Rights and
Provenance checklists; not independent review or production approval.

The contained film process already has explicit media-output limits. Its native
publication/retention path also applied the generic 128 MiB provider-response
ceiling, independently of those limits. The private guarded producer now carries
its checked original allowance through ingestion, native reopen, retention and
historical verification. Worker metadata has its existing separate 64 KiB bound;
media cannot borrow that reserve. Public external response handling remains at
128 MiB. The allowance is not deserializable and is not inferred from arbitrary
tool-result JSON.

Preview distinguishes FilmRender responses from external/other tools while
retaining the existing 1 GiB total native envelope, combined input/output/metadata
headroom, native-reader allowance, 32 response objects, 128 changed paths per phase
and 16 actors. Multi-GiB production still fails admission; no phase splitting or
actor-budget workaround is introduced. The process ceiling is not a claim that
native admission can accommodate it.

Close recovery first reconciles the original native handoff and verifies exact
retained coverage. Its existing callback then reopens the original result under
the film protocol read ceiling before any source clear. That read ceiling admits
no new output or publication. Normal close still checks the original worker and
request-bound allowance before entering the SDK close transaction. Object gates
drop before new index admission, as in the original qualified path.

- Editor/Sound: no render algorithm, cue clock, picture allocation, recording,
  output contract, source selection or media byte is rewritten by this change.
- Platform: preview reports the applicable response ceiling and still refuses
  oversized combined native admission before execution. External/comic bounds
  remain unchanged. This does not qualify episode composition or larger staging.
- Rights/Provenance: serialized receipts grant no producer capability. Actual
  guarded production, original operation identity, native retained coverage and
  historical byte reopen remain required. No creative approval, profile adoption,
  public release, scratch retirement or payload deletion is added.

Validation must cover both default and film builds, arithmetic/count/overflow
refusal, existing lifecycle/recovery cases and an actual above-128-MiB retained
film. Metadata tests with large byte counts and the existing streamed-file test
are not proof of that native publication lifecycle. The larger native fixture is
an open qualification gate; keep this source PR draft until it passes. Full
Season 5 resource/master and interruption qualification remains separately open.

The first actual fixture produced 384,177,485 payload bytes, with a largest
artifact of 187,625,580 bytes. Native publication, retained acknowledgement and
technical completion were recorded. Replaying after deliberate local result
metadata loss then exposed a remaining generic allowance in `resume`. That path
now decodes the checked original native controls and releases their object gates
before reconciling retention with the same film allowance. The preserved original
runtime, attempt, registration and retained owner are used by an explicit
continuation; no fresh render/admission is started. Completion of that continuation
and guarded close remains required before marking this qualification passed.
