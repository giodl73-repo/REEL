# Episode output records use the native scene contracts

Managed parent assembly previously retained checked media but offered no native
output-record or Git-proposal handoff. Episode jobs now accept the existing
scene job's record mappings and optional proposal settings. The shared exporter
receives the parent's sealed native result; it does not manufacture a producer
assertion from arbitrary files or an external JSON success flag.

The small records remain pinned to exact archived templates and definitions.
Preflight forbids overwriting production inputs or child output types. The
worker updates only declared output subjects, clears inherited review status,
preserves unmapped streams, and emits an unsigned claim, candidate index, records
and optional Git proposal. All artifact sizes and counts enter runner admission.
The request and worker report pin the record contract independently from the
media recipe: exporting a subject does not change the consumed production graph.

Before releasing temporary owners, handoff reopens the actual retained result
tree under its source fence. It verifies record bytes, claim correspondence,
native receipt, exact template changes and proposal settings. Repeated or
interrupted completion keeps the same contract; an altered mapping or damaged
artifact refuses. Candidate reads use explicit byte, request and reader ceilings
within the already admitted workspace allowance. No global cache lock is added.

Real acceptance also exposed missing retained component masters after expensive
child preparation. The coordinator now verifies declared master availability
before child compilation or source adoption and reports the exact segment and
object. No scan, hydration, implicit archive enrollment or current-producer proof
is inferred. The fixtures remove one named synthetic master and require refusal
with no source adoption, then restore it for the complete managed run.

Both complete CLI fixtures exercise capture with Git offline, checked parent
assembly, retained records, owner handoff, idempotent finish, changed-template
and changed-contract refusal, and damaged index refusal. After restoring the
fixture checkout, they check and create the proposal without changing HEAD,
index or working files, then explicitly cherry-pick it. Exactly one small parent
record changes; media stays in the synthetic cache.

Producer-applied rights/provenance checklist: records clear old approvals;
preserve byte, recipe and source identity; add no upload or creative approval;
keep private runtime paths and reports outside project Git. Git adoption is a
separate explicit operation. This is a checklist review, not independent
approval. Actual episode acceptance, hosted qualification, remaining native
families and installed consumer cutover remain separate milestones.
