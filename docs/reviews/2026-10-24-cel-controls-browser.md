# Cel controls browser review

Producer-applied Editor and Rights/Provenance checklists; no independent review,
human visual approval or delivery selection is implied.

The existing media export required working copies of primary images and a
compiled movie just to open the editor. Explicit `export-controls` now emits
the native, source-locked session without media resolution or cache access.
Only project/output/title fields are accepted. The UI labels the mode, hides
playback/previews and navigates declared clocks without an animation loop.
The complete media export remains available and retains its copy budget.

Portable tests exercise native scoped export/overwrite/ambiguous-spec refusal,
and actual UI handlers in media and controls-only modes for both session v3 and
v4. Existing native language/project/reader tests pass. Media-mode sessions keep
their current behavior; edit schemas and source locks do not change.

A frozen private bilingual episode passes isolated Edge interaction checks for
identity, reorder/comments, removal with exact cue fitting, undo/reset,
download/reopen, reload persistence, stale and cross-language import rejection,
cross-cue drag refusal and navigation. Both languages fit desktop/phone document
widths. No unexpected requests, page errors, media copies or server were involved.
Six browser drafts apply natively and pass twelve native language compilations.
Original controls and protected language controls stay unchanged; changed cel
sequences legitimately update the edited language's semantic markers while
recording clocks remain fixed. Compilation recipes use explicit descriptor graph
routes rather than historical filenames.

Private controls, drafts and reports remain project cache/LFS assets. This proof
does not cover images, audio decoding/playback, rendered-media review or human
visual acceptance. Runtime installation must retain exact source/executable
identity and must not retarget existing production jobs or start services.
