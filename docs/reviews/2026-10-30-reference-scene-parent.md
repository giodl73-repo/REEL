# Retained scene proofs as current episode components

`CompositionJobPlan::from_verified_components` admits independently verified
scene and presentation masters from one captured source. It requires exact
scene/output coverage, selected bytes and disjoint production/output definitions.
It does not construct a historical `CurrentScene` or fabricate a producer claim.
The original correspondence-based constructors retain their coverage gates.

```text
current primary scene controls + selected scene master
                         |
           source-owned primary comparison
                         |
           VerifiedScene + complete child resources
                         |
    compile current parent controls (authored conform unchanged)
                         |
    freeze -> finish/reopen provider -> protect parent source
                         |
     native ordered assembly + complete decode/clock comparison
```

The parent borrows each scene's live source/runtime/byte guards and retains its
complete flattened resource set and metadata root. Current selected movies are
composition inputs; they never become primary media. Generated parent controls
bind the exact proof declarations and current movies. Old receipts remain
historical and are not rewritten. Parent ownership cannot alias a child source.

The native kernel accepts a scene reference only through its sealed proof. It
checks the selected master and exact declaration, then uses the proof's guarded
path. Explicit scene input/output/control maps must cover only the remaining
historical components; a caller cannot shadow a verified scene. Native scene
verification sets the delivery flag, not the presentation flag. Original
layout, readiness, catalog, role order, output geometry, frame/sample counts and
full decoded ordered-assembly checks remain in force.
Lossless H.264 scene masters may use this sealed comparison instead of a
historical receipt; their complete native pixels and PCM still have to match.

Currentness checks bracket execution, including failures, and include every
borrowed scene and presentation owner. Withdrawal invalidates the matching scene
and any parent borrowing it, while unrelated owners remain usable. Explicitly
omitting historical scene jobs is safe only when the parent's retained proof
coverage supplies those scenes; an old constructor still requires its exact
historical job recipe map.

The tiny episode scenario changes one cel, leaves its authored conform intact,
hides source Git/records/definitions, jobs and preparation, and takes the obsolete
master out of the synthetic cache. All metadata is finished and reopened through
the existing provider before ownership. Checks cover missing scene proof coverage,
caller replacement, parent/child identity collision, complete child obligations,
decoded assembly and independent withdrawal.

This remains a low-level production primitive. Real execution requires the bounded
worker and capacity admission. A technical scene match does not prove its cue's
upstream text/generation basis, original approval, independent backup custody or
authority to evict. Unbound explicit source-text evidence is refused. Invocation
content/text freshness, bounded CLI orchestration and actual-project acceptance
remain separate cutover requirements.

Producer-applied editor, sound-designer and provenance checklists require all
ordered frames and PCM, retained byte guards, unchanged historical assertions,
privacy-safe evidence and no inferred creative approval. These are technical
findings, not independent review or production adoption.
