# Bounded episode jobs and retained-context handoff

The new `run-episode` command combines metadata-only resource planning, the
existing capacity/process-tree runner, owned scene/presentation comparisons,
current parent compilation and checked assembly. It restores one frozen source;
component owners remain separate from the runner's root fence. The profile must
name existing caches and stores, exact output filenames and explicit budgets.
There is no setup, daemon, Git checkout fallback or automatic approval.

Successful jobs retain and reopen their complete worker context before adopting
it under the root job and withdrawing temporary claims. `finish-episode` repeats
that metadata step safely without rendering. Temporary owners that have changed
are refused. The root remains a retained result; these steps do not authorize
payload removal or establish independent backup custody.

The actual CLI fixture uses four tiny retained scenes, including one compiled
projection and three declared contexts. Source Git/records/definitions and old
jobs are unavailable. It verifies all 96 assembled frames and PCM/timestamps,
reopens and hashes retained outputs, proves the root packet contains every
declared parent-context object, observes all five temporary claims withdrawn,
and repeats finish without journal changes. Reusing a completed render revision
and withdrawing an independently reused source are refused. Invalid output paths
are rejected before source adoption. The final exact-source fixture passes in
118.50 seconds. Strict locked all-target/all-feature Clippy, formatting and
325 enabled regression tests (224 library, 13 episode, 88 asset-resolution)
pass. Hosted qualification remains required.

The first capacity refusal correctly caught an undersized test budget. A worker
refusal exposed a relative staging directory; canonicalizing the worker-owned
directory fixed it. Failure diagnostics are bounded compressed assets, decoded
only by the synthetic test helper. Metadata retries reuse the pinned provider's
exact Busy classification and cumulative allowance, without a cache-wide lock.

Producer-applied editor/sound/provenance checks require exact native content and
clocks, live source/runtime/byte guards, complete declared resource retention,
unchanged historical claims and clear technical/creative boundaries. Local
observations do not constitute independent review. Failed-job cleanup and a
pending prepare/adopt recovery remain open, as do output-record/Git handoff,
generation/text freshness, actual project acceptance and production cutover.
