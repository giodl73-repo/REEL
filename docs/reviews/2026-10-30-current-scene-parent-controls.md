# Current scene controls for an unchanged parent conform

A changed scene master must travel with its current native job, semantic scope,
contract, production document and delivery receipt. Replacing only the movie pin
can leave the parent checking the previous job or reading its original directory.

`CurrentSceneControls::compile` derives those controls from a current matched
scene `JobPlan`. It recompiles into new bounded private preparation, verifies the
frozen interpretation, and requires the fresh job hash to match the guarded
selected delivery receipt. The receipt must bind the selected master. The
constructor rejects a wrong source, output, scene, job or receipt. Projected and
declared native job modes use their existing compiler paths.

Scene correspondence still requires independently admitted original producer and
claim evidence. This constructor cannot qualify an arbitrary legacy movie by
rewriting its receipt or relabeling a fresh plan as original production. A legacy
movie without that correspondence needs its own independent primary-reference
acceptance path.

Only the four render-control documents and the exact receipt are retained.
Intermediate authoring projections, compiler reports and diagnostic inventories
do not enter the parent dependency set. Bodies are bounded to 4 MiB each and
16 MiB together. Native JSON remains exact opaque bytes; native typed parsers
interpret it without imposing Tig's integer-only authored JSON rules.

`CompositionJobPlan::from_current_component_controls` binds these sealed control
sets to the exact current component correspondence and language. It also supports
current guarded presentations and an empty presentation set. The existing
constructors continue refusing changed scenes without their current controls.
The pinned conform provides order and layout. Effective scene references are
compiled in memory; the original conform and production receipts remain intact.

Current metadata uses the existing bounded Merkle framing and enters the frozen
parent's evidence. Missing pages refuse on readback. Assembly supplies these
compiled scene controls directly to the existing native kernel and rejects
caller replacements. Primary media and selected scene outputs retain their
separate guarded providers, with parent and child ownership checked before and
after assembly. Movies remain composition dependencies, never primary inputs.

Producer-applied editing, sound and provenance checklists require current scene
scope, complete job/receipt correspondence, exact sample/frame checks and
immutable historical evidence. This is not independent review, creative approval,
retained custody or eviction authority.

The synthetic fixture changes one cel, renders its scene and keeps the old
episode conform unchanged. It compiles current native controls, hides Git and
working records, hides preparation/render directories, removes the unneeded old
movie from its temporary cache, and assembles through the current retained
providers. Negative cases cover old receipt, wrong job, unrelated control key,
missing generated metadata and caller replacement. The temporary deletion tests
dependency independence; it does not grant production retirement permission.
Final local and exact-head hosted qualification is required before adoption.

Local qualification passes locked all-target/all-feature Clippy, 218 library
tests (nine explicitly ignored), all 13 episode tests, all 17 presentation-source
tests and the original complete fake-episode lifecycle (86.67 seconds). The new
explicit sparse-edit fixture passes in 95.18 seconds. CI explicitly runs that
fixture on Windows. Hosted qualification and actual mixed-project acceptance
remain separate requirements.

Remaining work includes source-text/generation-basis freshness, bounded parent
CLI/scheduler integration, complete child handoff and actual mixed-project
acceptance. This low-level primitive does not replace those steps.
