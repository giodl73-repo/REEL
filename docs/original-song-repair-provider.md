# Bounded provider execution from original song evidence

Build the explicit provider feature with
`cargo build --features song-provider --bin reel-song-repair`. Default builds keep
the existing pure commands and do not link the managed execution dependency.

The explicit `reel-song-repair plan-generation ADMISSION RECIPE EXECUTION` and
`generate ADMISSION RECIPE EXECUTION NEW_DIRECTORY` commands connect the
[verified original-source interpretation](mapped-original-song-source.md) to
the shared offline ACE repaint backend and the independent
[masked materializer](original-song-masked-repair.md). They do not invent a
modern original request or loosen generated-guide validation.

The caller must use an already admitted, bounded managed job and qualified tool
installation. These commands create no cache, capacity reservation, source owner,
publication, setup, service, download or selection. Normal managed input/tool
pinning, output declaration, retention, failure salvage and rollback remain
required. Direct execution is a trusted-program interface, not a sandbox or
independent qualification of the caller's declared backend.

The `reel.original-song-repair-execution.v1` file declares:

- `runtime`, `backend`, `backend_helper`: explicit `path` and exact `object` pins;
- an explicit private `caption`, `seed`, `repaint_mode` and `repaint_strength`;
- the exact original `permissions`: `private_only:true`, `external_upload:false`,
  `identifiable_imitation:false`, `public_release:false`;
- `timeout_seconds` (1–3600), `memory_bytes` (64 MiB–16 GiB) and `processes` (1–32).

Relative file inputs resolve inside the execution file's directory. Traversal
and relative escapes refuse. The helper must be the pinned adjacent
`local_song_backend.py`; the shared `local_song_repaint.py` supplies the separate
`--original-repair` route. The existing modern repaint path stays distinct.
CLI generation output may be an ordinary relative child path for a managed
workspace; the native API itself requires a new absolute directory.

The existing `reel.local-song-runtime.v1` descriptor must name the absolute ACE
root, its exact source commit, the installed Python pin and a nonempty
`generation_files` roster. No installation path is discovered or guessed.
At most 4096 generation entries and 16 GiB of unique installed files are admitted.
Each installed file is limited to 4 GiB.
Each named file is stream-hashed and kept open; on Windows the read handles deny
writes and deletion through provider execution and final materialization.
Corruption, absence or conflicting pins refuse before creating the output or
calling a provider. Validation can be expensive because it checks actual bytes.
An installation relocation requires an explicitly verified successor descriptor.

Native preparation re-inspects every original source input and holds the
admission, recipe, execution, runtime and script bytes. It writes a distinct
private source context and provider request, plus source-exact conditioning
windows derived from integer masks and five seconds of neighboring original
music. Those windows and provider inputs are also held read-only. Supplied words
come only from the recipe's exact canonical line ranges.

On qualified Windows execution, the existing shared Windows Job Object primitive
contains the child tree under the declared timeout, aggregate committed-memory
and process limits. Its bounded quiet route creates no unbounded process log.
The backend sets offline controls before model initialization. It uses fixed
batch size one, one call per declared patch, deterministic `seed + index`, eight
inference steps, no semantic planner and no automatic retry. It returns raw
provider audio and a private attempt receipt; it never rewrites the original
request or materializes the final full recording.
The qualified backend currently uses Spanish vocal conditioning; it does not
infer a source language or translate canonical words.

Native code checks receipt correspondence, attempt count, seed, context and raw
audio pins. The raw rate/channels must match. At most 0.1 seconds of latent-grid
tail drift is admitted, and every masked sample must be present. Native code
independently trims an excess tail or fills a missing tail with original context
only outside the mask, preserving the untouched raw provider file and disclosing
the exact frame counts. The normalized candidates then enter the independent
materializer and recheck. Original duration, float-WAVE format/container and
every protected sample bit remain unchanged.

Outputs retain source context, provider request/runtime, conditioning windows,
raw provider files, provider receipt, normalized candidates/roster, materialized
recording/receipt and a generation receipt. Declare the files needed for later
checks in the outer managed job. A successful controller call is an unselected
candidate; exact-word diagnostics, acoustic continuity, beat alignment, human
listening, source-interpretation authority, rights and release remain separate.
Partial outputs are preserved on failure. Existing output directories refuse;
there is no hidden retry or overwrite path.

Producer-applied review: reconstruction checks clocks, raw provenance and locked
samples; editing/sound checks changed boundaries by listening; lyric review keeps
supplied and performed words separate; provenance keeps the original request,
private restrictions and human authority distinct. Synthetic callback tests are
reported as not executing a provider. Actual managed provider execution,
retained readback, rollback and listening are required before lane adoption.
The explicitly ignored `explicit_python_child_obeys_native_input_guards_and_materializes_synthetic_audio`
test accepts `REEL_TEST_PYTHON` and exercises the contained child with synthetic
audio and attempted input writes. It loads no ACE model and grants no musical
or production qualification.
