# REEL v0.2.44 screen demo capture evidence — roles check

## Frame

ICELINES already renders one sealed Matchup card through CLI generation, TUI,
and Web owner systems. The missing capability is a portable receipt proving
the current bytes and required surface coverage of a reviewed capture set.

The deletion target is one manual cross-surface capture inventory. REEL must
not become a shell runner, browser automation framework, TUI recorder,
redaction oracle, accessibility checker, or product approver.

## Comparison

| System | Classification | Finding |
|---|---|---|
| ICELINES surface-parity ledger | Reuse | Owner source of truth for semantic parity and supported surfaces. |
| ICELINES Web capture script | Adapt | Fixed viewports, route readiness, PNG dimensions, and nonblank checks remain owner execution. |
| REEL provider image evidence | Adapt | Exact PNG verification is reusable, but provider lifecycle semantics are not. |
| VHS | Reuse externally | Strong code-authored terminal capture executor; scripts and commands remain owner-local. |
| Playwright | Reuse externally | Strong browser capture executor; browser behavior remains owner-local. |
| FFmpeg and OTIO | Reuse later | Composition and editorial exchange remain separate from capture provenance. |

## Five-role findings

| Role | Finding | V1 response |
|---|---|---|
| Editor | Capture order must be explicit but should not become an edit decision. | Contiguous owner sequence only; no durations, cuts, or selection. |
| Animation Director | Screen focus and zoom may later need choreography. | Deferred until real captures prove a reusable contract. |
| Platform and Audience | Viewport dimensions matter but do not prove mobile behavior or accessibility. | Decode and verify dimensions; preserve explicit non-claims. |
| Story Director | Product claims must remain tied to owner state. | Bind exact state bytes and sanitized owner state reference without asserting correspondence. |
| Sound Designer | Narration belongs to editorial assembly, not capture evidence. | No narration or audio fields in V1. |

## ICELINES roles

- KEEL: keep shared state and surface semantics inside ICELINES.
- CREST: technical evidence cannot approve visual quality.
- broadcast: PNG bytes cannot prove focus, reduced motion, responsiveness, or
  browser accessibility.
- TAPE: a screenshot cannot prove that visible numbers match sealed data.
- BENCH: missing surfaces, aliases, duplicates, stale dimensions, and overwrite
  must fail deterministically.

## Proof gates

1. One sealed ICELINES Matchup state document.
2. Distinct owner-created CLI, TUI, and Web PNGs.
3. One accepted path-free receipt.
4. Structured failures for missing surfaces, duplicate bytes, wrong dimensions,
   aliases, invalid PNG, and overwrite.
5. No claim that REEL verified screenshot semantics, redaction, accessibility,
   selection, publication, or release.
